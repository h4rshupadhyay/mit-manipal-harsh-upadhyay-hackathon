# Production Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete production local fitting/restoration, held-out trigger-policy selection, severity-sensitive development selection, and explicit backtest CLI composition without fabricating empirical inputs or results.

**Architecture:** Add a typed preregistered RuntimeDefinition and separate dataset-bound RuntimeEvidenceIndex at the existing fitter/runtime seam. Reuse verified local models and deterministic Confidence, Impact and Stress modules; freeze complete state for restore without fitting. Select policy entirely within each supplied training partition and preserve all old serialized fields/hashes.

**Tech Stack:** Python `>=3.12,<3.13`, existing Pydantic/NumPy/SciPy model stack, pytest, Ruff and mypy; no new dependencies.

**Spec:** [Approved production runtime design](../specs/2026-10-07-production-runtime-design.md).

## Global Constraints

- The user approved this full integration scope and sequential implementation; routine implementation decisions need no further permission. Follow the current `docs/development-workflow.md` publication authorization and branch state, not any stale ignored proposal's no-push note.
- Read AGENTS.md, CONTEXT.md, the approved spec, ADR 0008 and ADR 0010 before implementation. Preserve concurrent EventStudy/Unicode/chronology corrections and all user edits.
- Use the current agreed feature branch and IDE-visible checkout. Do not create/rename branches, rewrite history or move worktrees without existing authorization.
- Preserve CandidateFitter, FittedRuntime, BacktestDataset, TrainingPartition, FittedManifest, DevelopmentLock, RiskSignal and TriggerDecision interfaces and serialized field sets/schema literals. Existing objective/configuration/artifact JSON hashes must remain unchanged.
- Production empirical fitting rejects synthetic TrainingPartition evidence. Mechanics fixtures retain explicit project-authored simulation provenance/source terms and use only pytest temporary artifacts; neither fixtures nor injected backend results establish empirical quality.
- A RuntimeDefinition hash can be preregistered; a hash containing future event labels cannot. RuntimeEvidenceIndex is separate and bound to dataset_hash. Open only the supplied training cases during fit; restore opens no label/index files.
- No implicit downloads, refresh, fabricated confidence/impact/policy values, model weights in Git, final-result overwrite, or financial calculations in generative-model paths.
- No demo/presentation/submission artifacts or new runtime configuration with invented numeric empirical choices. Public terms remain Impact Score, Confidence, Portfolio Materiality and Action Priority as separate concepts.
- Run commands in the supported Python 3.12 environment using the repository dependencies; do not alter dependency pins or install extra dependencies to bypass a gate.
- Every checkpoint requires focused RED then GREEN, applicable full `pytest`, `ruff check .`, `mypy src`, independent spec/standards review, and a coherent green commit. The controller runs shell checks directly. Record unavailable checks honestly.

## Review Focus

- Historical hashes: widening objective support must not add serialization defaults or change any old record bytes; pin an old configuration and locked-artifact round trip in Task 5.
- Actual availability: a preregistered definition cannot hide future labels or late catalogue/market resources; test descriptor/source/outcome availability in Task 1 and strict freeze boundaries in Task 3.
- Multi-clause truth: one representative label must never label every clause/entity automatically; test target completeness, repeated mentions and unknown entities in Task 3.
- Evidence selection: missing material labels, incomplete valuation coverage and one-class subfit evidence must not turn into zero-loss/false labels or deployable no-alert policies; test explicit exclusions/no-selection in Tasks 2 and 4.
- Final resource failures: missing model snapshots or malformed fitted state must fail before final-attempt reservation; actual post-reservation inference failure must remain consumed, tested in Task 6.

## File structure and execution order

New files: `src/risk_engine/backtest/runtime_inputs.py` (definition/index/typed records and narrow training loader), `policy_selection.py` (auditable held-out candidate scoring and later fold planning), `runtime_state.py` (immutable fitted state and serialization validation), `runtime.py` (production adapter/composition), and focused matching test files under `tests/backtest/`. Add `tests/backtest/runtime_fixtures.py` only for clearly identified project-authored contract-simulation helpers; do not import it from production.

Localized existing-file edits: `risk/module.py` (Confidence identity helper), `impact/module.py` (read-only calibration summary), `risk/policy.py` (typed candidate criteria/evaluation with shared predicates), `backtest/module.py` (objective extraction), `scripts/run_backtest.py` (explicit CLI construction). Existing corresponding tests extend those behaviors. Do not split the large backtest module or refactor unrelated algorithms.

Tasks are sequential: 1 → 2 → 3 → 4 → 5 → 6. Dispatch one Sol implementer at a time with the active task plus the spec and preceding interface report. Each task is its own independently reviewable commit; do not batch all six into one checkpoint. Task 2's pure policy evaluation exists before Task 3 needs to serialize its audit type; Task 4 later adds chronological model replay.
