# Methodology and evidence boundaries

This document states the Financial Risk Engine's domain contracts, implemented deterministic methods, and conditions for an empirical claim. The current [results](results.md) are a fictional manual Stress Test only. No historical calibration, validated automatic trigger, or final Backtest has been completed. The [approved design](superpowers/specs/2026-10-04-financial-risk-engine-design.md), [domain vocabulary](../CONTEXT.md), and [methodology audit](research/methodology-audit.md) give the fuller rationale.

## Evidence, interpretation, and time

A **Source Item** carries its source reference, source terms, text hash, snapshot ID, publication and retrieval times, and provenance. News and social items that describe one story are clustered so a duplicated event cannot cross training and evaluation partitions as independent evidence. The replay cutoff and all availability comparisons use timezone-aware instants normalized to UTC. Event-to-market-session mapping uses an explicit calendar, local close, and observation cutoff; an elapsed embargo at least as long as the longest event window separates fitting from validation. Analysis replays supplied immutable snapshots and never refreshes a provider implicitly.

Local NLP components can link an entity and assign one of eight stable **Event Classes**: Geopolitical, Macroeconomic/Monetary, Credit/Default, Regulatory/Legal, Operational/Cyber, Corporate Action, Climate/Natural Disaster, and Other/Uncertain. Eight is a requirement-driven domain contract, not a discovered optimal taxonomy. **Sentiment** ranges from −1 to +1. An ambiguous or unknown entity is ineligible for automatic action. The **Risk Signal** retains the chosen entity, Event Class, rationale, evidence, source/version identities, and separate values for the concepts below.

| Field | Meaning |
| --- | --- |
| **Impact Score** | Conditional market-severity decile 1–10 on a fixed, versioned **Reference Basket**, independent of current holdings and Confidence. |
| **Confidence** | Calibrated probability that both entity link and Event Class are correct for the Source Item; it is not severity or analogue support. |
| **Portfolio Materiality** | Stressed loss on the current Synthetic Portfolio, in its currency and as a fraction of base value. |
| **Action Priority** | Portfolio-specific attention ordering; it does not replace the required Impact Score or itself authorize an automatic Stress Test. |

Confidence fitting needs independently labeled joint-correctness outcomes from chronological development data. Probability calibration and its Brier score, log loss, and reliability evidence are separate from decision-threshold selection. The code can implement these steps, but the present authored exercise supplies no such fitted empirical artifact. See [scikit-learn's calibration guide](https://scikit-learn.org/stable/modules/calibration.html).

## From observed market reactions to a Stress Scenario

For a real historical event, the event study aligns an exposed factor/security return and a declared benchmark to the same market sessions. Its **Abnormal Return** is the observed return less the return estimated from the benchmark; a registered window sums those values. A market model fits its normal-return relation before a declared gap, with a comparable-unit market-adjusted fallback when its estimation sample is inadequate. The benchmark, window, calendar, estimation sample, overlap exclusions, missing-data rule, units, and observation vintage must be frozen before outcomes are examined. Observed abnormal movement is associated with the event; it is not proof that the event caused it. This follows the established event-study method described by [MacKinlay](https://www.bu.edu/econ/files/2011/01/MacKinlay-1996-Event-Studies-in-Economics-and-Finance.pdf) and [ADR 0008](adr/0008-use-event-studies-and-historical-joint-scenarios.md).

An eligible **Historical Analogue** must have observed evidence available before the replay cutoff. A frozen matching configuration compares Event Class, region, exposure and any declared modifiers at ordered support levels. It records the candidates, support count, distance and selected IDs, backs off when support is insufficient, and abstains from an empirical claim when none qualifies. Nearest-neighbor distance ties resolve by event ID. The exact levels and minimum support are project choices requiring chronological development selection, not universal financial rules.

Each analogue retains one contemporaneously observed **Joint Shock Vector**: equity, rates, spread, FX, commodity, and volatility moves have explicit factor identities, units and horizon. The complete vector is replayed together; independently combining each factor's worst move would invent a historical scenario. A **Reference Basket** with fixed exposures, construction date, return snapshot and version converts each vector into comparable basket loss. Equal-risk-contribution, inverse-volatility and equal-notional basket constructions exist as candidates. Equal risk is a calibration-date property; contributions can drift later. The frozen historical loss distribution and a declared nearest-rank, lower-ties convention map expected basket loss to **Impact Score** 1–10. The score is ordinal: a difference of two deciles is not a fixed amount of money. Impact ≥8 means the upper three deciles of the frozen reference distribution, not automatically a catastrophe. [ADRs 0003](adr/0003-calibrate-impact-against-historical-market-reactions.md) and [0009](adr/0009-separate-market-impact-from-portfolio-materiality.md) describe these decisions; [Hyndman and Fan](https://robjhyndman.com/papers/sample_quantiles.pdf) explain why quantile conventions must be declared.

When observed analogue support is inadequate, a governed **hypothetical** Stress Scenario can still illustrate plausible joint moves. It must retain hypothetical provenance, assumptions, version and any analyst override lineage. A hypothetical vector may be located on a previously frozen decile scale, but it cannot be described as an empirically estimated event reaction. The currently committed scenarios are entirely in this category.

## Valuation and automatic action

The deterministic **Stress Engine** normalizes supported shock units, applies one complete Stress Scenario to the same Synthetic Portfolio, and calculates before/after value, loss, and attribution. Loans use expected-loss sensitivities, bonds use duration and spread approximations, and derivatives use declared delta/DV01 sensitivities. Unsupported exposures and missing coverage remain visible; they are not zero-risk assumptions. Currency conversion is not inferred from an absent FX input. The current approximation scope is specified in [ADR 0004](adr/0004-use-asset-specific-stress-approximations.md). A **Stress Test** is this scenario calculation; a **Backtest** is a separate, out-of-time assessment.

Automatic action needs a known entity, a selected and chronologically available policy, a bound calibrated Confidence target/version, Confidence at or above its selected threshold, Impact Score ≥8, supported exposure, matching Portfolio Materiality currency, and loss at or above a selected positive economic floor within declared tolerance. The economic floor prevents trivial positive rounding noise from triggering. The Confidence threshold and floor belong to inner held-out policy selection under the declared `material-event-f1-v1` objective; they are not arbitrary published defaults. Manual override is an explicit audited path. **Action Priority** orders analyst attention separately from the decision gates. See [ADR 0010](adr/0010-pre-register-and-chronologically-validate-project-conventions.md) and [scikit-learn's threshold guidance](https://scikit-learn.org/stable/modules/classification_threshold.html).

## Chronological development and final evaluation

A genuine evaluation requires source permissions; immutable dataset and model hashes; real source and market availability; independent entity, Event Class, material-event and reference-loss labels; complete observed joint factor vectors; and enough disjoint historical event groups, including relevant India cases. The runtime definition and its source terms, labels, factor/unit conventions, candidate resources and policy grid must be preregistered no later than configuration freeze. The development configuration freezes the candidate set, objectives, split rule, embargo and reporting plan before any selected outcome is inspected. A final period remains inaccessible during selection. No future observation, label, model snapshot or market vintage can enter an earlier fit.

Nested chronological development uses inner validation for candidate choice and outer held-out periods to assess that choice. The implemented one-standard-error rule chooses the lexicographically simplest candidate whose mean inner score is within one standard error of the best; the score direction, complete folds, candidate identities and complexity order are retained. The legacy `event-class-macro-f1` objective and `normalized-ordinal-impact-accuracy-v1` are distinct options. The latter equals `1 − ordinal MAE / 9` only when every scored case has an independent reference loss and there are no abstentions or missing severities. Policy selection uses separate inner held-out material-event labels and the preregistered Confidence/economic-floor grid; it does not tune the requirement-driven Impact ≥8 gate. Selection on the final period would bias performance estimates, as explained by [Cawley and Talbot](https://www.jmlr.org/papers/v11/cawley10a.html).

After development selection, an explicit frozen runtime must be restored against matching dataset, model, configuration and evidence hashes. The final Backtest is reserved and run once on an untouched period; a failed reserved attempt is consumed, and an immutable result is never overwritten. Any changed assumptions require a new version and a valid untouched holdout. [ADR 0005](adr/0005-validate-with-historical-backtests-and-case-studies.md) defines the historical aim. Current selected-configuration, cutpoint and development files are unresolved status envelopes, not fitted performance. No final result exists; the exact readiness and available manual calculations are in [results.md](results.md).

## What is established, required, and selected

Abnormal-return event studies, complete historical scenario replay, sensitivity revaluation, probability calibration and chronological validation are established methods. The eight Event Classes, Sentiment range, separate domain fields, 1–10 Impact contract and Impact ≥8 gate are product requirements. Basket construction, event windows, matching/backoff, quantile reference population, candidate objective, Confidence cutoff, economic floor and alert budget are project choices. They need versioned preregistration and independent evaluation before being called effective, calibrated, or optimal. The [methodology audit](research/methodology-audit.md) records alternatives and their evidence needs.
